📄
Synopsis

AI Study Buddy is a web application that allows students to upload their own study material (lecture notes, textbook chapters, PDFs) and interact with an AI that answers questions exclusively from those materials — a technique called Retrieval-Augmented Generation (RAG). Beyond Q&A, the system auto-generates multiple-choice quizzes, flashcards with spaced-repetition scheduling (SM-2 algorithm), short-answer evaluations, and AI-generated revision plans. Progress data is persisted in MongoDB, allowing the system to identify weak topics and personalise future study sessions. Everything runs in the browser with a clean, responsive React frontend talking to an Express REST API, which delegates AI work to a Python FastAPI micro-service that manages embeddings locally with FAISS.

⚠️ Planning

Problem Statement

The core challenge this project addresses.

🔴 The Problem

Students today have access to vast amounts of study material but lack an intelligent tool that understands their specific notes and helps them study effectively. Generic AI chatbots hallucinate or answer from general knowledge rather than the student's actual syllabus. Traditional flashcard apps and quiz platforms are static, requiring students to manually create content. There is no unified solution that combines AI-grounded Q&A, automated quiz generation, adaptive flashcards, and personalised revision planning — all anchored to the student's own material.

😓
Pain Point 1

Generic LLMs answer from general training data, not the student's actual lecture slides or chapter notes.

⏰
Pain Point 2

Creating flashcards and quizzes manually is extremely time-consuming, especially before exams.

📉
Pain Point 3

Students have no visibility into which topics they are weak at unless they take formal mock tests.

Objectives

The specific, measurable goals this system must achieve by the end of Week 11.

  • 1
    RAG-based Q&A Grounded in Student Notes
    The system must answer questions using only the text from uploaded documents. Answers must cite source excerpts with relevance scores above a configurable threshold (0.25).
  • 2
    Automated Quiz and Flashcard Generation
    Generate multiple-choice questions (4 options, answer index, explanation), short-answer questions, and two-sided flashcards with topic labels — all from the uploaded content using LLM prompting.
  • 3
    Spaced Repetition Flashcard Review (SM-2)
    Implement the SM-2 spaced-repetition algorithm to schedule flashcard reviews based on user ratings (Again / Hard / Good / Easy). Due cards are surfaced automatically.
  • 4
    Personalised AI Revision Planner
    Generate a day-by-day revision plan from the document content. Plans are saved as tasks in the planner with due dates. The last day is always a full revision and mock quiz.
  • 5
    Weak-topic Detection and Progress Analytics
    Track quiz attempt scores per document and per topic. Identify weak topics (below 60%) and strong topics (above 80%). Display a streak counter and trend chart of score history.
  • 6
    Secure Multi-user Authentication
    JWT-based register/login flow with bcrypt password hashing. All data is scoped to the authenticated user; no data leaks between users.
  • 7
    Responsive, Accessible Web Interface
    A clean React single-page app that works on desktop and tablet. Navigation, document upload, chat, study modes, and progress views all accessible from one interface.

Demo 2 — Register, Login & JWT Auth

Full authentication flow using bcryptjs and JWT. Demonstrates successful registration, successful login, and the exact error returned for a wrong password.

1
Register a new user
POST /api/auth/register. Validates email format, minimum 6-char password, and unique email. Hashes password with bcrypt cost 10 and returns a signed JWT.
routes.jsjs
// POST /api/auth/register
router.post('/auth/register', h(async (req, res) => {
  const { name, email, password } = req.body;
  if (!name || !email || !password) throw bad('Name, email and password are required');
  if (!/^\S+@\S+\.\S+$/.test(email)) throw bad('Enter a valid email address');
  if (password.length < 6) throw bad('Password must be at least 6 characters');
  if (await User.findOne({ email: email.toLowerCase() }))
    throw bad('Email is already registered', 409);
  const user = await User.create({
    name, email,
    passwordHash: await bcrypt.hash(password, 10)
  });
  res.status(201).json({ token: sign(user), user: { name: user.name, email: user.email } });
}));

// POST /api/auth/login
router.post('/auth/login', h(async (req, res) => {
  const { email, password } = req.body;
  const user = await User.findOne({ email: String(email || '').toLowerCase() });
  // bcrypt.compare returns false if hash doesn't match → same error either way
  if (!user || !(await bcrypt.compare(password || '', user.passwordHash)))
    throw bad('Wrong email or password', 401);
  res.json({ token: sign(user), user: { name: user.name, email: user.email } });
}));

JWT Auth Middleware — protects all private routes
Every route after login requires Authorization: Bearer <token>. Missing or expired tokens return clear errors.
middleware.jsjs
module.exports = function auth(req, res, next) {
  const header = req.headers.authorization || '';
  const token = header.startsWith('Bearer ') ? header.slice(7) : null;
  if (!token) return res.status(401).json({ error: 'Please log in' });
  try {
    const payload = jwt.verify(token, process.env.JWT_SECRET);
    req.userId = payload.id;  // scopes all DB queries to this user
    next();
  } catch {
    res.status(401).json({ error: 'Session expired, please log in again' });
  }
};

Demo 3 — PDF Upload & RAG Chunking

The first step of the RAG pipeline: upload a PDF through the Express API, which forwards it to the Python AI service, where it is extracted, cleaned, split into overlapping 200-word chunks, embedded with MiniLM-L6-v2, and stored in a FAISS index.

1
Step 1 — Text extraction from PDF
main.py – extract_text()python 
def extract_text(filename: str, data: bytes) -> str:
    if filename.lower().endswith(".pdf"):
        reader = PdfReader(io.BytesIO(data))
        return "\n".join((page.extract_text() or "") for page in reader.pages)
    return data.decode("utf-8", errors="ignore")
2
Step 2 — Split into overlapping 200-word chunks
Overlap of 40 words ensures context is not lost at chunk boundaries. Any chunk under 15 words (at the end of the document) is merged with the last valid chunk.
main.py – chunk_text()python 
CHUNK_WORDS = 200
OVERLAP_WORDS = 40

def chunk_text(text: str) -> List[str]:
    words = clean(text).split(" ")
    if not words or words == [""]:
        return []
    step = CHUNK_WORDS - OVERLAP_WORDS  # slide 160 words each time
    chunks = []
    for start in range(0, len(words), step):
        piece = words[start : start + CHUNK_WORDS]
        if len(piece) >= 15 or not chunks:  # skip tiny trailing fragments
            chunks.append(" ".join(piece))
        if start + CHUNK_WORDS >= len(words):
            break
    return chunks
3
Step 3 — Embed chunks & store in FAISS
MiniLM-L6-v2 encodes each chunk into a 384-dimension vector. Vectors are normalised for cosine similarity via inner product. Stored as .npy NumPy arrays alongside a JSON metadata file, per user.
main.py – Store.add()python
def embed(texts: List[str]) -> np.ndarray:
    return embedder.encode(
        texts, normalize_embeddings=True, convert_to_numpy=True
    ).astype("float32")

def add(self, doc_id: str, doc_name: str, texts: List[str]):
    vectors = embed(texts)
    for i, t in enumerate(texts):
        self.chunks.append({
            "doc_id": doc_id, "doc_name": doc_name,
            "order": i, "text": t
        })
    self.emb = np.vstack([self.emb, vectors])
    self.save()  # persist chunks.json + emb.npy

🧠 RAG Pipeline — What happens next

When the user asks a question, the AI service uses FAISS to find the top-k most similar chunks (cosine similarity via inner product on normalised vectors, threshold ≥ 0.25). These chunks are injected as numbered context into a Claude Sonnet prompt. The LLM is instructed to answer only from those excerpts and cite them like [1], [2]. If no relevant chunk is found, it returns the hard-coded "not found" message — preventing hallucination.
